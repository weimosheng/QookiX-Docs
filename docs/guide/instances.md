# 多实例管理

## 为什么要用多实例

每个实例都拥有**独立的**游戏版本、加载器、模组列表、资源包、光影与存档。这意味着：

- 生存档装了一堆模组，不会污染你的纯净速通实例；
- 同一个模组的不同版本可以分别测试；
- 重装或删除一个实例，其它实例毫发无损。

## 常用操作

在实例列表的卡片或右键菜单中，可以完成：

| 操作 | 说明 |
| --- | --- |
| 启动 | 运行该实例 |
| 设置 | 修改版本、加载器、内存、Java、游戏目录等 |
| 复制 | 整份克隆出一个新实例，适合做「对照组」测试 |
| 重命名 | 改名字不影响任何内容 |
| 打开目录 | 直接在文件管理器中定位该实例文件夹 |
| 删除 | 移除实例（会询问是否同时删除数据） |

::: danger 删除前请确认
删除实例会一并清掉它的存档。重要存档请先备份，或只删除实例配置、保留数据目录。
:::

## 推荐的实例组织方式

```
实例
├─ 1.21 原版生存        （原版，长期档）
├─ 1.20.1 Forge 大型模组  （Forge，重整合包）
├─ 1.21 Fabric 优化      （Fabric，钠 + 锂，低配流畅）
└─ 测试服               （临时验证模组兼容性）
```

小技巧：

- **复制实例做实验**：装可疑模组前先复制一份，出问题直接删副本。
- **按用途命名**：把版本 + 加载器写进名字，几个月后也能一眼认出。
- **分离存档**：不要把长期生存档放在随手创建的测试实例里。

## 导入与导出

需要换电脑或分享给朋友时，可以用实例的**导出**功能把它打包成整合包文件，在另一台机器上**导入**即可还原全部配置。

::: tip 分享前注意
导出前检查一下实例里是否夹带了自己的账号缓存、截图等隐私内容，必要时先清理。
:::

## 实例之间共享内容

模组、资源包、光影默认存放在各自实例目录内，互不干扰。如果你希望多个实例共用同一份资源包，可以在实例设置中把对应子目录改为共享位置——但请注意，共用目录意味着改动会同时影响所有引用它的实例。
